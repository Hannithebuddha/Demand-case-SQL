# Анализ продаж и качества прогноза в FMCG с помощью SQL

## О проекте

Этот проект — портфельный SQL-кейс на данных условной FMCG-компании **FreshBite Foods**, производителя продуктов питания.

Основная задача проекта — показать применение SQL к типовым задачам Demand Planning и анализа продаж: проверке качества данных, анализу объёмов, промо-зависимости и качества прогноза.

Проект сознательно сфокусирован на **объёмах продаж**, а не на выручке или марже, поскольку основной бизнес-контекст кейса связан с Demand Planning.

## Бизнес-задача

Компания наблюдает неоднородную динамику продаж и ухудшение качества прогноза.

Необходимо:

- проверить качество исходных данных;
- проанализировать динамику объёмов;
- определить различия между категориями и каналами;
- оценить влияние промо;
- сравнить Current forecast с фактическими продажами;
- рассчитать forecast error, bias и WAPE;
- определить основные источники ошибки прогноза.

## Каналы продаж

## Версии прогноза

## Логика, заложенная в тестовые данные

В синтетическом датасете специально заложены несколько FMCG-сценариев:

- категория Dairy растёт быстрее бизнеса в целом;
- Snacks сильнее зависят от промо;
- Beverages имеют выраженную летнюю сезонность;
- один крупный клиент постепенно снижает объёмы;
- часть SKU систематически overforecast;
- часть SKU систематически underforecast;
- отдельные продукты запускаются в середине периода;
- некоторые продукты имеют статус Discontinued;
- присутствует небольшое количество NULL, нулевых и отрицательных объёмов;
- специально добавлен дубль на ожидаемой гранулярности;
- присутствуют случаи forecast без actual и actual без forecast.

Эти особенности позволяют использовать проект не только для демонстрации SQL-синтаксиса, но и для проверки бизнес-логики данных.

## Результаты анализа

Ниже приведены результаты, полученные на синтетическом датасете после исключения NULL, нулевых и отрицательных объёмов из расчёта бизнес-KPI.

### Качество данных

В исходной таблице sales обнаружены:

- NULL в `quantity`: **1**;
- нулевой объём: **1**;
- отрицательный объём: **1**;
- строки, входящие в дублирующуюся комбинацию месяц × продукт × клиент: **2**.

Отрицательные значения не трактуются автоматически как ошибка: в реальных FMCG-данных они могут быть связаны с возвратами, сторно или корректировками и требуют проверки бизнес-смысла.

### Динамика продаж

Полный 2025 год вырос относительно полного 2024 года на **14.1%** по объёму.

Наиболее высокая динамика среди категорий — **Dairy: 18.2% YoY**.

2026 год не сравнивается с полным 2025 годом напрямую, поскольку фактические данные за 2026 год доступны только за январь–июнь.

### Промо

Наиболее высокая доля промо-объёма наблюдается в категории **Snacks: 42.4%**.

Это соответствует заложенной бизнес-гипотезе о повышенной промо-зависимости категории.

### Forecast Accuracy

Для версии `Current` на закрытом периоде январь 2025 — июнь 2026:

- общий Bias: **0.5%**;
- общий WAPE: **10.3%**;
- forecast без соответствующего actual в закрытом периоде: **819** комбинаций;
- actual без соответствующего Current forecast: **1** комбинаций.

Наиболее высокий WAPE среди категорий — **Snacks: 12.4%**.

Для regular-продаж WAPE составляет **8.6%**, для promo-продаж — **16.9%**. Таким образом, промо-периоды действительно прогнозируются хуже.

### Основные выводы

1. Рост бизнеса неоднороден по категориям; Dairy является одним из основных драйверов роста.
2. Snacks требует отдельного внимания при планировании промо из-за высокой доли промо-объёма.
3. Общий Bias близок к нейтральному уровню, однако это не означает отсутствия ошибок: WAPE фиксирует абсолютные отклонения, которые взаимно не компенсируются.
4. Для управления forecast accuracy целесообразно приоритизировать SKU по абсолютной ошибке, а не только по процентному WAPE.
5. Promo и regular demand имеет смысл анализировать отдельно, поскольку качество прогноза заметно различается.

## Ограничения кейса

- данные синтетические и созданы специально для демонстрации SQL-анализа;
- определения forecast KPI в разных компаниях могут отличаться;
- `Forecast Accuracy = 100% - WAPE` намеренно не используется как основной KPI: в проекте показываются непосредственно WAPE и Bias;
- отрицательные и нулевые объёмы исключаются из расчёта KPI, но в реальной задаче требуют отдельной бизнес-валидации;
- 2026 год содержит только шесть месяцев факта, поэтому полный YoY выполняется на 2024–2025 годах.
