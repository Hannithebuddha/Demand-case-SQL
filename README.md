# Demand-case-SQL
# Анализ продаж и качества прогноза в FMCG с помощью SQL

Небольшой pet-проект по SQL на синтетических данных FMCG-компании FreshBite Foods.

Мне хотелось собрать кейс, максимально приближенный к задачам, с которыми можно столкнуться в Demand Planning: проверить качество исходных данных, посмотреть динамику объёмов и промо-зависимость, а затем разобраться, где и почему ошибается прогноз.
Основной фокус проекта — объёмы продаж и forecast accuracy. Выручку и маржу сознательно оставила за рамками кейса.

## Что анализируем
В основе проекта четыре бизнес-разреза:
+ продукты и категории;
+ клиенты;
+ каналы продаж — Federal chain, Local chain, Discounters и E-commerce;
+ фактические продажи и две версии прогноза — Budget и Current.
Для оценки качества прогноза использую Current forecast.

Данные организованы в пять таблиц:
+ products — справочник SKU и категорий
+ customers — клиенты и каналы продаж
+ sales — фактические объёмы и promo flag
+ forecast — Budget и Current forecast
+ calendar — календарный справочник

#### Гранулярность факта:
месяц × SKU × клиент
#### Гранулярность прогноза:
месяц × SKU × клиент × версия прогноза

#### Что специально заложено в данные
Датасет синтетический, поэтому в него заранее добавлены несколько FMCG-сценариев, которые можно обнаружить в ходе анализа:
+ Dairy растёт быстрее бизнеса в целом;
+ Snacks заметно сильнее зависит от промо;
+ Beverages имеет летнюю сезонность;
+ один из крупных клиентов постепенно теряет объём;
+ часть SKU систематически overforecast, часть — underforecast;
+ есть новые и discontinued SKU.

Данные при этом не идеально чистые: присутствуют NULL, нулевые и отрицательные объёмы, дубль, forecast без actual и actual без forecast.
Это позволяет начать анализ не сразу с KPI, а с проверки качества и бизнес-логики данных.

### Что использовала в SQL
SELECT · WHERE · ORDER BY · GROUP BY · HAVING · JOIN · CASE WHEN · COUNT(DISTINCT) · CTE · подзапросы · conditional aggregation · функции работы с датами · NULL handling

Отдельный блок посвящён расчёту Forecast Error, Bias и WAPE.

## Структура анализа
##### 01 — Data Quality
Сначала проверяю сам датасет: период данных, количество SKU и клиентов, NULL, нулевые и отрицательные объёмы, дубли и соответствие справочникам.
Отдельно проверяю продажи до launch date и наличие ожидаемых forecast versions.

##### 02 — Sales Analysis
Дальше смотрю динамику фактических объёмов:
+ продажи по месяцам;
+ категории и каналы;
+ category × channel;
+ топ SKU;
+ годовую динамику;
+ новые и discontinued SKU;
+ динамику клиентов.

##### 03 — Promo Analysis
Сравниваю regular и promo sales и считаю долю промо-объёма по категориям и SKU.

##### 04 — Forecast Accuracy
Соединяю Current forecast с фактом на уровне:
месяц × SKU × клиент
и считаю:
+ Forecast Error = Forecast − Actual
+ Bias = Σ(Forecast − Actual) / ΣActual
+ WAPE = Σ|Forecast − Actual| / ΣActual

Дополнительно проверяю forecast без actual и actual без forecast и сравниваю качество прогноза для promo и regular demand.

##### 05 — Business Insights
Последний блок собирает основные аналитические выборки, из которых формируются выводы по кейсу.

## Что получилось

#### Продажи
+ В 2025 году общий объём вырос на 14,1% относительно 2024 года.
+ Самый высокий рост показала категория Dairy: +18,2% YoY.
+ 2026 год в полный YoY не включаю: фактические данные доступны только за январь–июнь.

#### Promo
+ Самая высокая зависимость от промо обнаружилась у Snacks: 42,4% объёма категории приходится на promo sales.
+ Для остальных категорий promo share заметно ниже.

#### Forecast Accuracy
На закрытом периоде январь 2025 — июнь 2026 для Current forecast:
+ Bias: +0,5%
+ WAPE: 10,3%
Почти нейтральный Bias при этом не означает отсутствия forecast error: положительные и отрицательные отклонения могут компенсировать друг друга, тогда как WAPE учитывает их абсолютную величину.
Самая высокая ошибка среди категорий у Snacks — WAPE 12,4%.
И здесь появляется наиболее интересная для меня связь:
+ Regular WAPE: 8,6%
+ Promo WAPE: 16,9%
То есть промо-периоды в этом датасете прогнозируются почти вдвое хуже regular demand.

### Что из этого следует
+ Dairy — один из основных драйверов роста бизнеса.
+ Snacks требует отдельного внимания в процессе планирования: высокая промо-зависимость сочетается с самым высоким WAPE среди категорий.
+ Для оценки качества прогноза недостаточно смотреть только на Bias. Почти нейтральный общий Bias скрывает разнонаправленные ошибки, которые становятся видны через WAPE.
+ При поиске проблемных SKU полезно смотреть не только на процент ошибки, но и на absolute forecast error: крупный SKU с умеренным WAPE может оказывать на общий результат большее влияние, чем маленький SKU с высокой  процентной ошибкой.
+ Promo и regular demand имеет смысл анализировать отдельно — характер ошибки прогноза у них заметно различается.

### Ограничения

+ Данные полностью синтетические и созданы для демонстрации SQL-анализа.
+ Определения forecast KPI могут различаться между компаниями, поэтому в проекте я показываю непосредственно WAPE и Bias, не превращая WAPE автоматически в универсальную метрику Forecast Accuracy.
+ Нулевые и отрицательные объёмы исключены из расчёта KPI. В реальных данных такие значения сначала потребовали бы бизнес-валидации: например, отрицательный объём может быть возвратом или корректировкой.
